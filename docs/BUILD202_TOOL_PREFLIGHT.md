# Build202：工具参数错误与授权错误分离

日期：2026-11-05；版本：1.0.9 / Build202。

## 现场与结论

用户截图中的失败项是 `read_context`，不是 `propose_patch`。旧的注册表 preflight 将“工具名称未下发”与“名称已下发但参数校验失败”合并成“调用不属于本轮已下发的工具和授权 ID”。因此 AI 可能将分页超限等参数问题误判成用户没有授权，并停止后续开发。

已用 `read_context(ref="message:0", limit=8192)` 复现相同错误。截图没有展开原始参数，无法确认用户这一次究竟是 limit、offset、额外字段还是其他参数有误；本例是代码路径复现，不冒充用户的实际参数。

## 修复

1. 区分 `invalid_arguments`、`tool_not_advertised`、`tool_unavailable`、`authorization_changed`；反馈准确的工具名、嵌套字段路径与限制。
2. 参数错误明确提示“未执行、无需重新授权”，模型收到可修正重试的结构化 recovery。授权失效和越界仍拒绝。
3. read_context 明示 limit 是 1–4096 个 UTF-16 单位，默认 4096；可省略并用 next_offset 续读。保持原有分页上限，不把全部历史灌回上下文。
4. 手机工具详情显示可读错误，不显示给模型用的恢复元数据；项目选择类工具显示具体标题。

未修改 developer prompt、人设、技能、记忆、项目数据或审批策略；没有自动重放失败的写操作。
