# Build 208：会话授权与响应状态

版本：1.0.9 / Build 208；日期：2026-11-07。

## 修复内容

- 当前项目／会话授权不再按固定 30 分钟到期，也不再因为一次网络中断或停止任务而撤销已选择的会话权限档。
- 停止／异常结束会清除待执行的单次审批凭据；切换会话和手动撤销仍使原权限失效。准备好的操作预览仍有自己的有效期，审批仍绑定请求指纹且只能消费一次。
- 项目／会话绑定、原文前置条件、授权路径、符号链接与敏感路径检查保持不变。取消会话定时器不扩大权限。
- 新增单调时钟驱动的响应活动状态：实际收到思考、正文或工具调用时才记为内容进展；SSE 心跳和其他原始字节仅记为网络活动。
- 15 秒无语义内容后显示等待状态；原始数据也停止时显示距最近数据的时间。15 秒只是状态提示阈值，不取消请求、不自动重试、不重新执行工具。
- 思考卡区分“正在接收思考”和“等待思考数据”。字数仍是本地文本长度，不冒充供应商计费 token。
- 网络超时仍受现有 NSURLSession 策略控制（请求无活动 180 秒，资源上限 1800 秒）；超时提示保留会话授权，要求核对已完成操作后手动继续。不保证 iOS 无限后台运行。
- 修复 Build 207 流式内部标记检测对普通结尾字符的误判：不完整的标记前缀短暂缓存，确认是普通内容或正常结束后原样发出；完整内部标记仍被隔离。本次不迁移或重写已保存的历史消息。

## 参考与实现

仅参考 OpenMinis 的流式等待计时结构，用 Objective-C 独立实现，没有复制 Swift 代码或人设正文。

- 上游：https://github.com/OpenMinis/OpenMinis
- 核对提交：`1a71df0f381cefde80bf912b723de6f9831bc177`
- 参考文件：`src/ios/Agent/Chat/AIChatViewModel+SSEStream.swift` 中的每流等待监测、等待事件前后计时与结束取消。
- 没有声称 OpenMinis 使用与 Dylix 相同的会话权限生命周期；会话授权改动依据 Dylix 自身项目边界与审批模型完成。

## 验证方法与限制

1. Foundation 策略测试：无固定到期、手动撤销、会话切换、过期预览、单次审批、路径与符号链接约束。
2. 真实 AIRuntime + 本地桩：多轮工具、错误／停止后保留会话档并清除审批、会话切换撤销、普通文本及分片内部标记。
3. 活动计时单元测试：静默、零字节、心跳、恢复内容、跨轮重置，使用可控单调时间，不需真实等待 30 分钟。
4. 本地 HTTP 服务器 + 真实 NSURLSession／SSE 解码：先返回思考，18 秒仅发送心跳，再恢复正文；检查等待／恢复及完成／取消时清理计时器。
5. 原生模拟器界面回归与设备编译；具体结果在 `BUILD208_TESTS.json`。

本地协议桩不等于付费模型实测；没有使用用户 API 密钥，也没有在实际反馈用户的设备上复现。应用资源中的人设和 FLEX 插件分别核对 SHA-256，保持原内容。
