## 发现与修复

1. Chat 解码器会将 `reasoning_content` 存为 `deepseek_reasoning`，但请求构造器只在特定 DeepSeek 协议/模型并且连接、模型一致时回传。此前上下文投影将所有 `provider_items` 都计入预算，并把包含该字段的消息视为不可整理。GLM 等普通 Chat 中转站的本地思考文本因此可能既不参与实际请求，又阻止历史工具压缩。
2. 新增带当前连接的投影入口。按照现有请求构造器的真实回放条件，只保留当前连接/模型实际使用的 provider_items。普通 Chat 闲置推理副本、切换模型后不再使用的状态，仅从网络投影与预算中排除；不删除本地原文。保留有效 DeepSeek reasoning_content、Responses encrypted_content 和 Gemini 原生 parts/thoughtSignature。
3. 原先每批工具折叠成一张带多条 JSON 的回执，批次数很多时仍有较高占用下限。现在必要时将连续的已完成旧批次进一步合成有界归档目录，每段最多 32 批，保留原始消息序号区间、首尾调用引用、工具数量与有界的失败/提案/构建事实；明确标记预览不完整。全部原文仍可按现有 read_context 精确读取。
4. 归档不能越过用户指令、独立 AI 回复、原生协议续接或未完成批次，不更改最新两批工具的配对、执行参数、审批和当前工程内容。
5. 上下文用量新增“未用于当前连接的推理副本”排除量与“工具回执合并归档”批数。应用硬保护预算不变，不能通过提高预算来掩盖历史累积。

## 验证

- `ContextProjectionRun.py`：119 项，包括原有 103 项；合成 280 批工具场景原始 1,688,611 字节，保守保留全部推理时仍为同样大小并被 777 KiB 拦截；带当前 GLM Chat 连接投影后 64,885 字节，旧历史 56,932 字节；排除闲置 provider 数据 732,200 字节，224 批回执合并归档。另覆盖 500 批极小结果：即使逐条回执比原文更大，也可直接合并旧批次，避免绕过整理。输入原文逐字节不变，归档结果可回读。
- `ContextRuntimeRun.py`：实际 AIRuntime + 确定性传输夹具，验证逐轮传入当前连接、600 KiB 闲置推理不再阻断发送、本地最终会话仍保留原始推理；不是外部真实模型请求。
- `AITransportNetwork.py`：136 项，含五种协议的实际 TFAIRequestBody 对照；去掉闲置状态前后的真实协议请求完全一致，需回放的状态不变，连接/模型切换后只排除原请求已不使用的状态。使用本机 HTTP/URLSession 测试夹具，无真实 API 密钥或计费。
- `ToolPreflightRun.py`：沿用工具参数恢复与权限检查回归。
- 保留 Build 203 全环境动态库签名修复；独立运行签名回归。
- 私有与开源源码分别编译设备包；验证版本、ZIP、主 App/扩展签名、人设资源以及 FLEX manifest。

## 边界

这是发送投影优化，不是删除用户历史或无损的模型记忆。归档中省略的细节仍需模型主动回读，旧工具结果也可能过期，写入前仍应重新检查真实文件。64 KiB 为可整理历史目标，不是承诺任何会话总量恒小于 64 KiB。用户输入、系统指令、最新观察以及确实需要的原生协议状态仍占用空间，无法安全整理时继续明确拦截。
