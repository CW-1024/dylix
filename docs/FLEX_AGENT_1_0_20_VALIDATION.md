# FLEX 1.0.20 / Dylix 1.0.7 build188

日期：2026-11-05。

## 本期实现

恢复独立 AI 状态悬浮球，以可拖动的两行胶囊呈现。收起聊天后显示，点击返回保留的同一会话、连接、模型与任务；不引入暂停按钮，不因收起而停止轮询。展开聊天后隐藏，断开配对后隐藏，App 离开前台时隐藏。

状态由现有 Remote job 事件和本地 FLEX 命令驱动：

- 连接检查、在线、连接中断。
- 读取控件/视图/类、截图、执行其他工具、本机构建。
- 模型处理、回复文字、等待人工确认、完成、停止与请求未完成。
- 页面点击、手势、滚动、视图修改和 FLEX 页面控制时提示“AI 操作中 · 请勿触屏”。这是提示，不拦截整个屏幕的人工触摸。
- 连续 15 秒未收到新的任务事件时显示等待更新的秒数，不生成虚构进度或思维内容。沿用已有 1 秒轮询，不新增高频网络请求；已处理的事件序号不会反复改变状态。

窗口不会成为 key window，只有胶囊范围接收触摸，其他位置穿透。拖动限制在安全区域，松手吸附左右边缘。适配浅色/深色，VoiceOver 提供标题、状态和返回提示，减少动态效果时停用旋转及吸附动画。

新增窗口被明确排除在目标 App 的窗口选择之外，即使人工选中悬浮球也不会把它当作目标控件树或截图窗口。

## 覆盖层与测试指引

chat_status 新增 targetReady、statusVisible、uiTransitioning、activity。targetReady 只有在聊天不可见、FLEX 覆盖层隐藏且不处于窗口切换时才为真。悬浮球不计入目标阻挡覆盖层。手势覆盖层保护仍保留；错误明确要求重新最小化并核对 targetReady，不自动关闭用户打开的工具页、不绕过权限。

FLEX 发送上下文同步更新：收起后有状态悬浮球；触摸前确认 targetReady；截图压缩像素不能直接当触摸坐标，坐标以 windowBounds 为准；实例保留不等于销毁重建/复用测试；隔离构建前先确认入口，不能先写散落测试文件再把准备工作当成测试成功。

没有修改模型工具 schema、当前项目构建范围、审批与授权边界，没有新增依赖，也没有加入生命周期动态追踪或任意方法调用。

## 用户本轮真机报告的结论

1. hookEvidence、类信息、头文件查询和页面导航已有实际返回，是有效进展。
2. false 标记表示工具没有观测调用轨迹、没有自动认证稳定性，不是查询失败。仅切换 Tab 后同一个实例仍存在，不能证明按钮销毁重建或列表复用稳定。
3. 旧 live ID 过期后重新查询是正确恢复，单次过期不能归因于 Logos 或 Hook；需要比较新旧签名、实例及页面状态。
4. 报告前段截图/窗口尺寸与末段截图尺寸有出入，应区分窗口逻辑点和压缩图片像素。报告未提供截图变换关系，不能把不同尺寸说成相同。
5. 首次手势被覆盖层拒绝，重新最小化后可操作。报告不足以确定是谁再次显示覆盖层；本期改善状态可见性与诊断，不虚称已经复现并根治自动重新显示问题。
6. 构建没有执行，所以构建 ID、产物即时索引及手机文件页刷新在该轮均未验收。新目录不等于新构建项目；当前 build_project 无目录覆盖参数。可在 Dylix 新建独立测试项目，再由 FLEX 选择它后测试，不修改业务根配置。
