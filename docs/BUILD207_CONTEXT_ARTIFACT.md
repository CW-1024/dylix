# Build 207：上下文压缩标记隔离

## 现象

长时间在同一项目会话中执行工具后，模型偶尔会把 `[DYLIX_CONTEXT_OFFLOADED]`、`arguments_ref`、`result_ref` 等历史压缩索引原样回复。该内容本来只用于模型上下文内部回读，不是用户回答。

## 修复

- 压缩批次和历史目录继续明确标为不完整事实、不可作为新动作；正文不会要求模型复述索引。
- AIRuntime 对流式文本做跨分片检测，标记被拆在多个 delta 时也能识别；命中后立即停止继续展示内部片段，显示普通的历史整理提示。
- 完成消息和会话持久化前再次兜底过滤，旧会话已经保存的标记也不会继续作为本轮模型上下文直接暴露。
- 原始完整会话未删除，`read_context` 的精确引用和分页仍可用；工具执行、审批、项目文件和人设不变。

## 验证

- `tests/ContextRuntimeRun.py`：运行时回归通过，覆盖普通长回复、工具批次、600 KiB 推理副本、流式拆分标记和持久化隔离。
- `tests/ContextProjectionRun.py`：121 项上下文投影检查通过。
