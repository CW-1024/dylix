# Dylix 1.0.5 build146

- 优化方案保留三个常用预设，高级选项按需展开。新增独立的符号处理：自动裁剪（默认）、保留完整符号；项目可跟随全局。
- 自动模式：-O0 保留完整符号，其他优化级别通过内嵌 LLD14 的 -S 去除调试记录。LLD14 的 -x 尚未实现，本次不声称移除全部本地符号或达到 Mac strip -S -x 的体积。
- 每个包类型保留 DebugSymbols 完整 dylib 副本，记录裁剪前后 SHA256、UUID、大小；symbols.json 将完整函数符号映射到经过段内容及地址验证的发布 UUID。
- 逐段核对代码、运行数据、异常展开信息及虚拟地址。发生差异或处理失败时停止导出和打包。
- AI 可查询和修改全局 symbolPolicy；项目通过 propose_build_settings 提案设置 auto/keep，构建返回实际处理记录。

## 验证

- 内嵌 Clang/LLD14 的 ARM64 Objective-C KVC 异常与 C++ 抛出/析构/捕获测试通过；篡改 __text 后验证器拒绝。
- auto + O2 开启，auto + O0/debug 及 keep 关闭的策略测试通过。
- 使用既有 AutoMessage 28 个对象文件和原链接参数：2,111,984 → 1,652,552 字节，减少 459,432 字节（21.8%）。代码/数据/异常展开段验证一致。本次未对裁剪后的 AutoMessage 做真机注入测试。
- 正常 App 构建入口生成 rootful/rootless/roothide 三种包，全部成功；逐包提取 dylib，SHA256 与处理记录一致，完整副本存在。
- 两种 IPA 均使用 iPhoneOS26.0 SDK 构建，最低 iOS15；软件内部插件默认仍为 SDK16.4。IPA 为 unsigned 产物，需按既有流程签名安装。

处理采用额外链接生成发布副本，构建链接时间会增加。完整调试副本与对象文件仍占本机空间；本功能减少导出插件体积，不自动清理工作区。
