# Dylix 1.0.4 Build 137 排查与验证

## 截图问题
1. 大补丁：提案生成时曾把各文件完整 before/after 再发送给模型，超过运行时 512 KB 返回限制，成功提案被替换成错误。现在只返回 proposal_id、路径、大小和摘要；完整差异仍保存在本机用于批准与事务备份。
2. 头文件读取：旧代码把不存在、目录、非普通文件和超过 20 MB 混成同一条大小错误。现在分别报实际原因并提示通过 list/search 核对完整路径；截图中文件的实际存在状态需用原授权目录复测，未凭截图断定文件缺失。
3. 大目录：移除总条目超过一万立即失败的判断；每页扫描最多100项，返回 total_entries/scanned_entries/next_offset，支持一万以后的偏移；搜索同时匹配文件名与正文。正文读取保留资源预算，不上传整个授权目录。

## AI 与软件互通
- read_app_state：真实设置、可编辑字段、当前会话可用工具清单，普通会话和项目会话均可使用。
- set_app_settings：主题、代码字号、优化等级、默认SDK、最低系统、deb/dylib产物开关、联网检索、后台音频辅助。修改后读回实际值。SDK与最低系统配对校验，主题即时生效，音频经后台协调器影响活动任务。
- create_directory：创建项目目录及缺失父目录，之后可创建源码或下载到该目录；权限层也覆盖嵌套目录创建。
- git_stage：仅对明确选择的源码路径暂存或取消暂存，复用原生Git服务；与提交、推送保持完整链路。
- 原有项目选择/创建/克隆、读写补丁、SDK覆盖、编译、产物清理、Git、联网、本机二进制与classdump工具继续保留。
- 本次不是“每个页面的所有操作已经全部工具化”：连接及密钥管理、任意存储分类清理、会话文件分享/导出、通知系统授权等仍有未接通项或需要系统选择界面。工具清单以真实注册结果为准，不把提示词描述当实现。
- 外部目录保持用户授予的只读范围；项目写入与全局设置走现有确认界面，不伪造系统授权。
