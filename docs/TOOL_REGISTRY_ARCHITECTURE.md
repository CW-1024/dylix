# 分层工具注册表实施方案

日期：2026-11-04；基于1.0.7（163）。

实施状态：已完成于1.0.7（164）。使用入口、接口说明见[TOOL_REGISTRY.md](TOOL_REGISTRY.md)，已执行测试和真机待验收范围见[BUILD164_TESTS.md](BUILD164_TESTS.md)。

现有AIRuntime分别组合TFAIToolbox、应用动作、附件、binary_inspect、ClassDump及Agent schema，执行时各自校验。项目写入、Git和构建保留原有prepare/审批/execute路径；附件目录保留原security-scoped书签及越界校验；binary_inspect仍只接受暂存输入。

新增Registry层统一声明名称、描述、读写属性、作用域、权限档、审批策略、前台要求和模块。运行前从真实根目录、授权有效性、暂存副本、前台状态、编译资源、MCP已授权工具等生成环境；未知工具默认拒绝。模型仅收到经过过滤的原schema，执行前再次检查环境和参数；审批回调后再复查，防止撤权与切后台竞态。混合app_action还逐项过滤动作枚举与发现目录。

A档沿用当前项目、暂存二进制、原生应用服务与只读Agent；技能/MCP/JS浏览器/记忆/队列提供独立本地开关。记忆正文显式读取，写入仍走项目补丁审批；摘要只本地。关闭队列后普通构建继续执行，繁忙时拒绝重复启动。

B档附件与授权目录只在本轮仍有效时下发；调用的具体ID再次核对。Remote仅查询显式开启且运行中的服务，返回状态白名单，不返回授权码、凭据或设备令牌。

C档设置默认关闭；用户原生界面手动登记一个App目录或确认属于自家插件的日志文件，无扫描。能力探测只读取这个精确目标；不根据rootful/rootless目录名判定越狱。元数据只读Info.plist白名单，日志分页读取。每次读取也必须原生人工确认，目标指纹批准后复核；本期没有C写工具，因此不存在绕过确认/快照的C写入入口。任何二进制分析仍需显式导入并暂存到现有binary_inspect，不提供复制/注入/动态执行工具。

验证：Foundation注册表/参数/开关单测；真实运行时schema与撤权测试；iOS模拟器前台与审批集成；两种SDK26设备编译；原保护文件哈希复核。越狱真实可读路径和签名真机仍需设备验收。独立Objective-C实现，仅参考OpenMinis注册/预检/条件下发结构，不复制Swift，不采纳AzTuT默认开启策略，不引入依赖。
